# Run Instructions

## 1. Prerequisites

- Install Docker Desktop and start it using Linux containers. On Linux, Docker Engine with the Compose v2 plugin also works.
- Install Git if cloning the repository, or download and extract the repository ZIP.
- Internet access is required for the initial build and external user profile lookups.

Java, Maven, and PostgreSQL run inside Docker; no separate installations are needed.

## 2. Get the project

Clone your repository and enter its folder:

```sh
git clone https://github.com/tmedina-dev/send-money-service.git
cd <repository-folder>
```

Replace the placeholders with the actual repository URL and folder. Your working
directory must contain `pom.xml`, `Dockerfile`, and `docker-compose.yml`.

## 3. Start the backend and database

```sh
docker compose up --build -d --wait
```

No `.env` file is required for the demo defaults. The first build downloads
dependencies and can take several minutes. Database tables and demo data are
created automatically through Flyway.

Check both services are healthy:

```sh
docker compose ps
```

## 4. Open and test the API

Open **http://localhost:8080/swagger-ui/index.html** in a browser on that device.
Expand **Wallet**, select `GET /api/v1/wallet`, click **Try it out**, enter
`X-User-Id: 1`, then **Execute**. A successful request returns HTTP 200 and the
user's balance and external name.

Postman can use the same endpoint and header. The OpenAPI JSON specification is
at **http://localhost:8080/v3/api-docs**.

Optional pgAdmin connection: host `localhost`, port `5433`, database
`local_wallet`, username `postgres`, password `root` (demo defaults).
The Docker database is separate from any PostgreSQL already installed locally.

## 5. Logs, stopping, and updates

```sh
docker compose logs -f app
docker compose down
docker compose up --build -d --wait
```

Press Ctrl+C to leave live logs. `down` stops and removes containers while
preserving database data and dated file logs in named volumes. After pulling
code updates, rerun the startup command to rebuild the backend.

**`docker compose down -v` deletes the database and log volumes.** Use it only
when intentionally resetting this device's demo data. Another device starts
with its own fresh data; these instructions do not copy your existing database.

## Troubleshooting

- If ports are occupied, create `.env` in the project folder with `APP_PORT=8081`
  and/or `DB_PORT=5434`, then run the startup command again. Use the new ports in
  your browser or database client.
- For startup errors, run `docker compose logs --tail 100 app db`.
- Existing `.env` files or shell variables can override Compose defaults. Changed
  database credentials do not update an already initialized database volume.
